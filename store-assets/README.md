# Store assets

| Folder | Holds |
| --- | --- |
| `microsoft/listings.json`, `listings.md` | The Store listing text in every locale, and the claims it makes (see `listings.md`) |
| `manifest.json` | Every Store screenshot in listing order: its raw source, theme, crop, en-US caption and alt text (LIST-8); `{locale}` in a path stands for each listing locale |
| `raw/microsoft/<locale>/` | The raw captures, one folder per listing locale: the test VM's whole desktop at 200% display scale, each with the `.json` sidecar the capture helper writes |
| `microsoft/screenshots/<locale>/` | The listing screenshots, rendered from that locale's raw captures, with the generated first screenshot (`00-hero-dark.png`) |
| `microsoft/text-free/` | The hero's one text-free copy, drawn from the en-US capture, for a web page |
| `capture/` | The capture scripts and the synthetic data each language shows (`sample-data.json`) |
| `web/screenshots/` | The images the repository README shows |

## Screenshots

Captured from the real installed app with synthetic data, never from a personal machine (LIST-8). Every listing language has its own set, fully localized: Windows itself, the app and the sample data are all in that language (en-CA and fr-CA reuse en-US and fr-FR). Every shot is in dark mode on the Windows 11 dark wallpaper (`img19.jpg`), on a 1920 x 1080 desktop at 200% display scale (3840 x 2160), which the renderer reduces to the Store size. The captions in `manifest.json` are the en-US `screenshotCaptions` in `listings.json`, in the same order and count; each other locale has its own translation there. The maintainer approves a new or changed set from the English screenshots and one sample language; the other languages must pass the automated checks.

The test VM has no Immich server, so the library comes from the repository's fake Immich server serving its sample library, named in the language being captured, and the app does the rest for real:

| Element | Source |
| --- | --- |
| The server (`https://photos.example.net` in en-US; each language's `server` in `capture/sample-data.json`) | The fake Immich server with `--library` ([tests/fake-immich](../tests/fake-immich/README.md), "Sample library"), behind a session-only Caddy proxy with `tls internal`, so the Connection page shows a normal https address; the guest's hosts file points the language's name at the proxy, and Caddy's root certificate is trusted only inside the throwaway guest |
| The photos, the user ("Alex Rivera" in en-US), the partner ("Jordan Lee") and the album names | The sample library: 48 CC0 photos from Wikimedia Commons with no recognisable people, and synthetic people on `example.invalid` addresses; each language's people and album names come from `capture/sample-data.json`, which the fake reads with `--locale` |
| The drive folder (`C:\ImmichDrive`) | A synthetic `settings.json` holding only `SyncRootPath`, written before the first launch, so no Windows account name appears in a path |
| The API key | The fake's test key, shown masked |

Shot 00 is the generated hero (below). Shot 04 shows the tray flyout and uses the `tray` crop; the others use the default `window` crop. The settings window is 1100 x 700 and the Explorer windows 1200 x 700, centered. The month folder names (`2026-08 August`) come from the app in a fixed culture, so they read the same in every language. Shot 03 shows the `2026-08 August` folder at a 160-pixel icon size, set through the window's shell folder view; it is opened from Explorer's Home by clicking the ImmichDrive entry in the navigation pane and then the folder, so the pane shows the drive selected (opening the `C:\ImmichDrive` path directly selects This PC instead); shot 05 shows the drive root in Details view. For shot 04 the settings window is closed and the tray icon is promoted out of the overflow (`IsPromoted` under `HKCU\Control Panel\NotifyIconSettings`, inside the throwaway guest).

1. **Capture** on the Windows 11 test VM (`windows-dev`) with the windows-build-tools app-test helpers, one language at a time, in a throwaway session per language. Switch Windows to the language on the base disk first (`app_test_language <locale>`, then a cold cycle), because a `-snapshot` session loses the change with its overlay. Then start the session: an uncommitted compose override adds `-snapshot` through the image's `ARGUMENTS` setting (check it is in QEMU's command line before Windows boots). Fetch the sample library and start the fake with `compose.sample.yml` and `SAMPLE_LOCALE=<locale>`, then the proxy on the VM's network, answering every language's server name. In the guest, add the hosts entry for the language's server name, trust the proxy's root, install the Release dev package and run `screenshot-desktop.ps1 -Mode Prepare -Scale 200`. Then run `capture/capture.sh <locale>` from this repo's root: it runs `capture/capture.ps1` in the desktop session, which writes the synthetic settings (the drive folder and the app's language), connects from the Connection page and captures each scene, finding every control by automation ID, and copies the captures into `raw/microsoft/<locale>/` under the manifest's names. `CAPTURE_PREPARE_LOCALE` can name a command that does the per-language steps above, so one `capture/capture.sh` run loops over every listing language. Afterwards run `app_test_clean`, stop the VM and recreate it from the base compose, remove the fake and the proxy so nothing persists, and switch Windows back with `app_test_language en-US`.
2. **Render** with `npm run shots:render` (winui-app-kit's renderer; its README has the rules): each locale's captures are cropped to 1366 x 768 in logical pixels and each 2 x 2 block averaged, with nothing composited or shaved, and written without an alpha channel to `microsoft/screenshots/<locale>/` (ASSET-9). It renders nothing while any listing locale lacks a capture. Recaptioning needs no recapture; a new look does.
3. **Check** with `npm run check:screenshots` (part of `npm run validate`): every listing locale has every capture, each with its sidecar, taken dark, at 100% or 200% scale, with effects on and the dark wallpaper; every screenshot was written by the renderer at exactly 1366 x 768; the captions match the en-US `screenshotCaptions`; no stray file is present in a locale folder.
4. **Sync** with the next Store release: the Store workflow's `screenshots` input uploads every locale's set, its hero first, with that locale's captions from `listings.json`, and keeps the listing's logos. Check the draft in Partner Center before submitting it.

A UI change that shows in a screenshot means recapturing that shot.

## The first screenshot: a generated hero

Store search shows only the first screenshot, at about 320 x 180, so it is a generated hero (D-123): the split layout, a gold brand panel with the icon, name, headline and subline on the left, beside the real UI enlarged from that locale's `raw/microsoft/<locale>/02-thumbnails-dark.png` on the right: File Explorer showing the drive with real thumbnails, since Explorer is where people use ImmichDrive. Each listing locale has its own, drawn from its `heroHeadline` and `heroSubline` in `listings.json`; en-CA and fr-CA use en-US's and fr-FR's. Its caption is the subline. `npm run hero` draws them (devkit, through winui-app-kit's `scripts/devkit`), and `npm run check:hero` in `validate` fails when one no longer matches its inputs or a listing locale has no capture. The text-free copy is drawn from the en-US capture. New or changed headlines are approved by the maintainer, like any screenshot.
